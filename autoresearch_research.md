# Autoresearch Research: AI Disaster Response ML Model Exploration & UI Upgrade

## Objective
Audit the existing AI Disaster Response project, perform literature/market research on disaster risk prediction ML, formulate defensible novelty, systematically train and ablate ML models under strict resource constraints (RTX 3050 4GB), and integrate the best model into a modern, lightweight UI with fluid micro-animations. Target publishable research contribution in disaster risk ML.

## Publish Venue
NeurIPS (ML for Social Good track) or ICML (Applied ML track). Focus on practical ML contributions with verified novelty.

## Metrics
- **Primary**: novelty_score (0-100, higher is better) — NEWness + DIFFERENTness + potential impact
- **Secondary**:
  - sota_gap_pct — improvement over best published flood risk prediction result
  - contrast_score (0-100) — how paradigm-distant from prior work
  - proof_strength (0-100) — rigor of math/experiment backing
  - prior_art_clear (0/1) — novelty check passed

## Research Resources (nearest venues for this topic)
- **Primary**: NeurIPS (ML for Social Good, RobustML), ICML (Applied ML), KDD
- **Databases**: arXiv cs.LG, cs.AI, Papers with Code (disaster prediction leaderboards), Semantic Scholar
- **Key domains**: Flood risk prediction, environmental ML, geospatial ML, tabular deep learning, uncertainty quantification

## High-Index Targets
- XGBoost and gradient boosting on tabular data (strong baselines)
- Graph Neural Networks for geospatial disaster modeling
- Physics-informed neural networks for hydrology
- Transformer architectures for tabular data (TabTransformer, FT-Transformer)
- Uncertainty quantification methods (MC Dropout, Deep Ensembles, Conformal Prediction)

## Constraints
- No fabricated results or citations — all claims must be verifiable
- Novelty check mandatory before any keep — search arXiv, Semantic Scholar, Papers with Code
- Every equation must be numerically verified (equations.md)
- Resource budget: RTX 3050 4GB, max 16GB RAM, no cloud GPU for baseline runs
- Model size < 50MB for deployment, inference latency < 100ms
- Preserve backward compatibility with existing API endpoints
- Git commit required for every kept idea

## What's Been Tried
- Baseline: XGBoost classifier with StandardScaler + OneHotEncoder preprocessing
- Features: 6 raw features + 2 engineered (runoff_index, drainage_inefficiency)
- Dataset: 500 synthetic samples generated by heuristic rules
- Nepal regional override: rule-based demo for 10 cities
- Model accuracy: needs evaluation (not yet run on current setup)

## Current Architecture Summary
- **Backend**: Flask (Python) with XGBoost for flood risk classification
- **Frontend**: React (Vite) with Leaflet maps, Axios HTTP client
- **ML Pipeline**: pandas → sklearn preprocessor → XGBoost → label decoder
- **Prediction Flow**: Input features → Feature engineering → Preprocessing → XGBoost predict → High-risk threshold override → Response
- **Classes**: Low, Medium, High risk (3-class classification)
- **Key Limitations**: Synthetic data only, no real-world validation, no uncertainty estimates, no temporal modeling, Nepal-only demo region, basic UI without micro-animations
